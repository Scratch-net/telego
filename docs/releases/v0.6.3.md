# v0.6.3 — Bounded WEB I/O and Middle-End diagnostics

This release bounds WEB bridge requests and adds evidence for Middle-End failures. It preserves healthy connection lifetimes and the existing Nginx TLS architecture.

## Bounded WEB bridge I/O

- Session creation, uplink, and downlink requests each have a 90-second budget for retries, headers, and the complete response body.
- The bridge limits response bytes during the read. Session creation requires exactly eight bytes.
- Downlink batches use the configured byte target. One complete protocol frame can exceed that target.
- Each WebSocket has a 90-second deadline to open. This deadline does not limit the lifetime of an open connection.
- Page closure cancels pending body reads and WebSocket establishment.

## Middle-End failure diagnostics

- Failed repairs record their stage, duration, safe error classification, and original slot identity. Telego captures this evidence before candidate cleanup.
- Intentional cancellation does not count as a failed repair. Repair failures do not increase physical-link failure totals or affected-binding totals.
- gnet diagnostics include received wire bytes, write attempts, and outbound buffer progress. These values do not prove peer delivery or TCP acknowledgment.
- On Linux, the owner callback captures `TCP_INFO` before socket closure. The snapshot includes TCP state, retransmission counters, RTT, and the send congestion window.
- A close during a write marks outbound progress as incomplete. Explicit availability states distinguish missing TCP evidence from zero-valued measurements.
- A socket follow-up supplies close evidence if the original failure precedes the close callback. It preserves the original identity without another failure count.
- Failed-repair transport evidence describes the replacement candidate. The slot identity still describes the failed incumbent.
- All diagnostic classes share the existing journal of 256 unacknowledged records. Diagnostic records exclude raw errors, addresses, credentials, client identities, and packet contents.

With SOCKS5, TCP evidence describes the socket to the proxy, not the remote Telegram connection. Log emission does not guarantee durable storage.

## Regression coverage

- Rendered-JavaScript tests cover response limits, request deadlines, WebSocket establishment, and cancellation across all four WEB carriers.
- Middle-End tests cover failed repairs, cleanup timing, socket availability, and closure during a write.
- CI installs Node.js 24 for the bridge tests. Node is not a dependency of the Telego binary or its Docker images.

## Upgrade

Existing TOML configurations remain valid. This release adds no required configuration keys and does not change the container logging driver.

Keep Nginx as the TLS endpoint. Restart Telego after the upgrade.

The [WEB guide](https://github.com/Scratch-net/telego/blob/v0.6.3/docs/web-proxy.md) and [Middle-End guide](https://github.com/Scratch-net/telego/blob/v0.6.3/docs/middle-end.md) describe the limits and diagnostic fields.

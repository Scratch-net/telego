# v0.6.6 — WEB reconnect recovery and dependency updates

A failed WebSocket lane opening no longer interrupts existing WEB traffic when another lane remains usable.
Extra reconnect diagnostics now require debug or trace logging. This release also updates Go and package dependencies.

## WEB reconnect recovery

- An opening error, close, or timeout closes only the failed lane when a usable sibling lane exists.
- Telegram receives a CLOSE for that lane and can open a replacement. Existing lanes continue to carry traffic.
- Without a usable sibling, the bridge retains its full reconnect behavior.
- Tests cover both diagnostic modes, continued traffic, replacement lanes, duplicate close events, and full reconnect recovery.

## Optional diagnostics

Extra WEB diagnostics require `[general].log-level = "debug"` or `"trace"` at startup.
At normal log levels, the bridge sends no diagnostic requests or diagnostic WebSocket close reasons.
Telego allocates no bridge diagnostic state or WebSocket diagnostic counters in this mode.
The recovery fix remains active at every log level.

Debug records cover bridge failures, individual WebSocket closures, and internal proxy stream closures.
Reports use authentication, bounded fields, and rate limits. They exclude credentials, packet contents, and raw error text.

To enable diagnostics, set the log level to `"debug"` or `"trace"`.
Then restart Telego and reconnect the WEB clients.
A live log-level change filters server output but does not change the diagnostic mode of an existing bridge page.

## Dependencies and builds

- Both Go modules now require Go 1.27.1. Docker build images use the same version.
- Updates include gotd/td 0.162.0, compression libraries, Pion dependencies, and the Go `x` packages.
- The local gnet source remains based on 2.10.0. Its dependencies and test dependencies also receive updates.
- The local gnet lifecycle, poller, and buffer ownership patches remain in place.
- The standalone `benchmark` directory is removed.

## Upgrade

Existing TOML configurations remain valid. This release adds no required configuration keys.

Restart Telego after the upgrade. Keep the existing Nginx TLS configuration.
Source builds require Go 1.27.1 or later and the complete repository, including `third_party/gnet`.

Read the [WEB guide](https://github.com/Scratch-net/telego/blob/v0.6.6/docs/web-proxy.md) for carrier behavior and debug diagnostics.

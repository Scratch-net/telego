# TeleGO v0.8.5

## Download backpressure

The Linux relay now pauses upstream socket reads when output capacity is exhausted.
It retries retained input before it accepts more socket data.
Partial forwards follow the same rule, including edge-triggered reads and EOF handling.
Slow clients can resume without the relay closing a valid download at the input limit.
Pending writes, connection close, and shutdown remain available during a read pause.

WEB output reads now fill a batch across queued entries, up to the existing 64 KiB read limit.
This reduces excess allocation capacity after short reads.
Partially consumed entries retain their allocation charge until the complete entry drains.

## Upstream connection recovery

Alternative DC connection attempts start after a 250 ms head start for the first endpoint.
At most two attempts run concurrently.
Failed attempts advance immediately, and cancellation closes and joins losing attempts.
The bounded dialer serves direct DC routes and Middle-End endpoint selection.

TCP receive and send buffers now use operating-system autotuning instead of fixed 512 KiB requests.
The benefit depends on the kernel, latency, and available bandwidth.
The measurements do not establish a universal throughput improvement.

## Dependency and tooling refresh

Updated Brotli to 1.3.0, klauspost/compress to 1.20.4, Pion transport/v5 to 5.1.5, and the compatible Go support libraries.
Go remains at the latest stable compiler, 1.27.3.
The latest x/exp revision requires its matching x/tools pseudo-version.
Upstream-only module-graph entries retain their existing versions.

Updated Playwright to 1.65.0, pyee to 16.0.1, the Chromium test browser, Docker login action, and container image pins.
The NGINX examples retain NGINX 1.31.8 with its refreshed Alpine image.

The default race, gc_opt race, production-tag, and 32-bit production-tag suites passed.
Both Go modules pass go fix and go vet with default and production tags.
Lint, NGINX integration, Python dependency checks, transfer-tool tests, and the Chromium launch check passed.
All three Linux release targets build successfully.
The vulnerability scan found no affected imported packages or reachable vulnerable symbols.
Its module-only OpenPGP advisory concerns a package that Telego does not import.

The preceding candidate completed native and synthetic download-pressure tests on Linux.

## Upgrade

Restart Telego after the binary or container update.
This release requires no new configuration.
Existing secrets, proxy links, and carrier values remain compatible.
EOF can reach the client later while output is blocked because the relay preserves unread upstream data until capacity returns.

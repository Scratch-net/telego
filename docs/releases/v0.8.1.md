# v0.8.1 — WEB transfer progress and queue accounting

## HTTPS uploads

HTTPS uploads now charge body storage separately from actual DATA frames.
A shared application reserve replaces the maximum frame reservation for each request.
Four ordinary upload batches can use the existing window without premature item exhaustion.
Session and global queue limits remain unchanged.

Later batches preserve capacity for missing earlier batches, including cancelled requests and retries with larger bodies.
Ready lanes share application capacity in FIFO order.
Control frames can proceed without DATA capacity.
Ordered delivery and byte-identical retry checks remain intact.

Authenticated upload rejection now preserves HTTP 503 behind Nginx with request buffering.
Telego sends the retry response, discards the declared body within a fixed deadline, and then closes the connection.
Previously, an early close turned normal backpressure into HTTP 502 and ended the WEB session.
Rejected bodies do not consume queue storage.

## WebSocket and download ownership

WebSocket admission accounts for actual DATA frames and temporary copies of fragmented input.
Queued input retains its queue charge until its final owner releases it, including after session closure.
HTTPS poll responses and replay buffers retain shared ownership without duplicate charges or premature capacity release.

## Toolchain and dependencies

Docker builds now use the published Go 1.27.3 images directly.
Pion DTLS updates to v3.1.15.
The local gnet patches remain intact.

## Validation

Regression tests cover four concurrent uploads, cancelled predecessors, retries, global queue saturation, lane fairness, and shutdown ownership.
The complete race, production-tag, 32-bit, lint, build, and Nginx checks passed.
An isolated Nginx test preserved HTTP 503 for all 12 buffered upload rejections.
Manual VPS tests completed large uploads, batch uploads, and downloads with the private release candidate.

## Upgrade

Restart Telego after the binary or container update.
Existing secrets, proxy links, and carrier values remain compatible.
This release requires no additional configuration or frontend update.

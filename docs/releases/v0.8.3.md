# v0.8.3 — Proxy reliability and lower overhead

## Connection and shutdown reliability

Direct DC and splice relays now drain queued responses after an orderly upstream EOF. The final response tail remains bounded and is released when the client drains or the deadline expires.

IP limiter release keys identify the entry generation. A late connection release can no longer decrement a replacement entry after eviction.

STUN probes use bounded, context-aware datagram retries and ignore malformed or unrelated responses. DC probes now treat timeouts and local read errors as failures.

TLS certificate and ServerHello refresh workers stop and join during shutdown. Failed refreshes retain the last successful cache entry.

## Lower per-request overhead

HTTPS batch validation and reservation now inspect only streams touched by the batch. Sequential frame behavior and rejection atomicity remain unchanged.

Response-pressure selection considers eligible bindings while preserving the existing ranking and accounting policy.

Metrics collect one fresh snapshot per source on each scrape.

Middle-End decryption writes plaintext directly into its pending buffer, removing an allocation and copy per input chunk.

WEB pending-frame cleanup clears unused references so closed streams do not retain large backing buffers.

## Logging and configuration

Zerolog events use a bounded asynchronous diode queue. Queue-full and post-shutdown drops are counted by `telego_log_dropped_messages_total`. Shutdown and fatal exit drain queued logs for up to two seconds.

The configured upstream `num-event-loops` value is now honored. Zero retains automatic loop selection.

`tcp-buffer-kb` remains accepted and validated for compatibility, but has no effect.

## Benchmarks

The 128-stream WEB validation and reservation benchmark decreased from approximately 4.8 µs to 24 ns, with zero allocations.

Pressure selection across 10,000 eligible owners decreased from approximately 124 µs to 39 µs. With 100 eligible owners among 10,000, it decreased from 93 µs to 0.4 µs. Selection retains zero allocations and the same victim ranking.

Middle-End decryption allocated 16 KiB instead of 32 KiB per 16 KiB input chunk, and 64 KiB instead of 128 KiB per 64 KiB chunk.

## Validation

Default and `gc_opt` race suites, production-tag tests, 32-bit production-tag tests, gnet regressions, Nginx integration, vet, and lint passed.

The private VPS candidate passed authenticated HTTPS checks and `doctor`. A large-file upload and mobile download completed with 48 ready Middle-End links, no dropped logs, and no restart or OOM.

## Upgrade

Restart Telego after the binary or container update. This release requires no additional configuration. Existing secrets, proxy links, and carrier values remain compatible.

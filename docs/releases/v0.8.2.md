# v0.8.2 — WEB reliability and lower allocation overhead

## HTTPS and WebSocket reliability

The bridge retries temporary HTTP failures with status 408, 429, 502, 503, or 504 within the original request deadline.
HTTPS replay accepts an absent or newly supplied Content-Length while it preserves the existing byte and cursor checks.
A replacement downlink poll promptly retires a stalled response writer before it reuses the response buffers.

WebSocket heartbeats now run independently of downlink traffic.
Continuous downloads no longer prevent Ping frames from reaching the peer.
Only accepted inbound traffic and Pong frames refresh peer liveness.

## Lower hashing overhead

Internal replay, request, configuration, and connection-limit fingerprints now use XXH3-128.
HTTP upload processing computes the body fingerprint once and passes it to session processing.
Each received retry still computes a fingerprint from its own body.
Session authentication compares the complete token in constant time without a separate token hash.
Protocol-required cryptography remains unchanged.

## Buffer reuse and fewer copies

The packet decoder reuses scratch buffers through a bounded atomic cache.
The cache retains less than 4 MiB of idle buffer capacity across the process and adds no mutex or waiting path.
Decoders clear written bytes before they return buffers, and completed packets retain independent storage.
Large drained buffers no longer belong to idle sessions.

The private Middle-End encoder encrypts its own frame buffer in place.
This removes one allocation and one full frame copy from each encode operation.
Public encryption calls preserve caller-owned plaintext, and returned ciphertext remains independently owned.

Local benchmarks for repeated 512 KiB packets reduced decoder allocations from six to one per packet.
Allocated bytes decreased by approximately 79% in the serial decoder benchmark.
Private frame encoding uses one allocation instead of two.

## Validation

Regression tests cover retries, replay metadata, stalled writers, continuous-download heartbeats, token comparisons, and buffer ownership.
Buffer tests include concurrent reuse, capacity limits, plaintext cleanup, repeated closure, and continuous CBC state.
Race suites, production-tag tests, 32-bit checks, lint, and Nginx integration passed.
The VPS candidate passed authenticated HTTPS checks and an upload/download test with exact file contents.
Go 1.27's leak detector reported no leaked goroutines after the transfer test.

## Upgrade

Restart Telego after the binary or container update.
Reload the bridge page to use the updated retry and replay behavior.
Existing secrets, proxy links, and carrier values remain compatible.
This release requires no additional configuration.

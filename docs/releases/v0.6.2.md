# v0.6.2 — Middle-End maintenance and connection lifetime

This release removes shared delays between Middle-End probes and repairs. It also preserves healthy connections across generation rotation without the former 90-second retirement deadline.

## Independent link maintenance

- Each physical slot has its own probe and repair worker. A slow slot no longer delays probes or failure detection on other slots.
- Repair replacements must complete preparation, including the handshake and a matching RPC pong, within 10 seconds before new bindings can use them.
- Each failed slot permits one repair attempt at a time. Failed repairs use bounded retry delays with jitter, and shutdown waits for worker cleanup.

## Generation lifetime and recovery

- Healthy links in a retiring generation keep their existing bindings and independent probes. This policy also covers healthy links that remain after a generation failure. New bindings use the active generation.
- Retiring generations do not repair or refresh links. Telego closes unused old links after their bindings, queues, and pending work are empty.
- Telego permits at most two live generation managers, including a candidate and unfinished cleanup. Another candidate first requires closure and cleanup of the oldest retiring generation.
- Capacity retirement can interrupt old bindings. The current active generation stays available during candidate preparation, but a failed candidate cannot restore those interrupted bindings.
- Scheduled artifact fetches continue during candidate retries. Recovery uses the latest valid artifact plan, including new content that supersedes a failed rotation attempt.
- A return to the applied artifact content restores that content as the recovery source. An already matching healthy generation needs no replacement.

## Failure diagnostics

- A bounded journal retains the first 256 unacknowledged physical-link failures or capacity retirements. Overflow increases `telego_middleend_diagnostic_records_dropped_total`.
- Each retained record includes the generation role, affected bindings, and a fixed failure or retirement reason. Physical-link records also include the slot, classified error, probe history, and queue counts before cleanup.
- Diagnostic records exclude raw errors, addresses, credentials, client identities, and packet contents. Records without client impact use INFO, while client impact and overflow use WARN.
- `telego_middleend_forced_retirement_total` and `telego_middleend_forced_retirement_affected_bindings_total` distinguish capacity retirement from physical-link failure. Their `reason` values are `artifact_capacity` and `recovery_capacity`.
- Generation identities, slot incarnations, probe identities, and error text do not become Prometheus labels. Log emission does not guarantee durable storage.

## Cache lifetime and test reliability

- Replay and blocked-IP caches now check expiration during access without background cleanup goroutines. This removes workers that retained discarded caches. Replay hits preserve their original expiration deadline, while rejected retries refresh blocked-IP deadlines.
- The Middle-End reservation test accepts both valid completion timings and checks FIFO request identities. Fake-clock regressions cover cache lifetime and expiration without scheduler-dependent sleeps.
- Dependency checks run the 22 regressions for Telego's local gnet patches, not the upstream test suite. The three supported build modes remain covered.
- Shared test gates limit parallelism and execution time. On Linux with cgroup v2 and a systemd user manager, `make test-limited` adds a hard 2 GiB memory limit and disables swap.

## Docker images

Release images now explicitly include `linux/arm/v7`, alongside `linux/amd64` and `linux/arm64`.

## Upgrade

Existing TOML configurations remain valid. This release adds no required configuration keys. The former 90-second retirement deadline was internal, not a TOML key.

For Go integrations, remove uses of `GenerationSupervisorConfig.DrainTimeout` and `ErrGenerationDrainTimeout`. These exported identifiers no longer exist.

Keep Nginx as the real TLS endpoint. Restart Telego after the upgrade.

The READMEs, sample configuration, and [Middle-End guide](https://github.com/Scratch-net/telego/blob/v0.6.2/docs/middle-end.md) describe the new maintenance, retirement, and diagnostic behavior.

# v0.6.7 — Automatic Middle-End startup and WEB performance defaults

Telego now starts Middle-End (ME) automatically unless the configuration explicitly disables it.
The gateway installer and WEB examples select `websocket-lanes` for maximum WEB performance.

## Middle-End startup

- An absent `[middle-end]` section or `enabled` value now enables ME. An explicit `enabled = false` still disables it.
- Telego prepares ME connections in the background. New clients use direct DC connections until ME is ready.
- If ME setup fails, direct routing remains available while Telego retries. Existing direct connections retain their route until they close.
- INFO logs report successful ME establishment, unavailable ME connections, and explicit disablement.
- Private direct routes complete public-IP discovery before they open ME TCP connections. Cold STUN discovery no longer leaves those sockets idle before the handshake.
- Public direct routes and SOCKS5 connections still bypass STUN. ME continues to use the exact TCP source port.

## WEB configuration

- The gateway installer now defaults to `websocket-lanes`. Its Nginx configuration already forwards WebSocket upgrades.
- The configuration examples and WEB guides recommend `websocket-lanes` for maximum performance.
- Existing explicit carrier values retain their behavior. An absent or empty `carrier` still selects `https` for compatibility.
- Carrier selection remains explicit. A failed WebSocket connection does not switch the session to HTTPS.

## Monitoring

The optional health dashboard omits the mean completed response-wait panel and gives the remaining wait panel the full row.
Wait duration metrics remain available for diagnosis. The panel bundle now contains eight health panels and three summary panels.

## Upgrade

Restart Telego after the upgrade.

If the configuration contains `enabled = false` under `[middle-end]`, remove that value to use automatic ME startup.
To keep direct-only routing, retain or add this explicit override:

```toml
[middle-end]
enabled = false
```

Automatic ME startup also enables its existing resource and admission limits.
The default permits 10,000 accepted client connections, including clients on direct fallback.
Direct ME connections behind NAT still require the public IP and preserved TCP source ports.

For an existing WEB installation, set `[web-proxy].carrier = "websocket-lanes"`.
Forward WebSocket upgrades through every reverse proxy.
Then restart Telego.
Reconnect the WEB clients.
To retain an older gateway installation's HTTPS lanes, pass `--carrier https-lanes` when you rerun the installer.

Read the [ME guide](https://github.com/Scratch-net/telego/blob/v0.6.7/docs/middle-end.md) and [WEB guide](https://github.com/Scratch-net/telego/blob/v0.6.7/docs/web-proxy.md) for configuration requirements.

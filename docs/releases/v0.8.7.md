# TeleGO v0.8.7

## Process reliability

The gnet acceptor no longer stops the engine when `accept` fails with `EMFILE`, `ENFILE`, `ENOBUFS`, or `ENOMEM`.
It pauses, backs off, and accepts again.

Telego exits with a non-zero status if the public listener, the WEB server, or the Middle-End network runtime stops without a signal.
Shutdown after SIGTERM or SIGINT has a limit of 25 seconds. A second signal stops the wait immediately.
SIGHUP and a closed stderr pipe do not stop the process.
The systemd unit now sets `Restart=always` and `TimeoutStopSec=30`.

`general.max-connections` now applies in every mode.
When it is 0, Telego calculates it from the `RLIMIT_NOFILE` soft limit: `(limit - min(256, limit / 2)) / 2`.
`[middle-end] max-connections` can only lower this value.

The log queue keeps 1,024 slots for warning and error events.

## FakeTLS and replay protection

The DD replay key now covers bytes 8 to 56 of the handshake frame.
A FakeTLS ClientHello that is rejected for its timestamp stays in the replay cache until that timestamp expires.
Some clients send their uptime instead of a Unix timestamp. Telego accepts such a timestamp only when it is below 120 seconds, the same as telemt.

Telego builds each ServerHello from a template parsed from the mask host.
The ServerHello echoes the client session ID, uses a fresh key share, and selects a cipher suite and group that the client offered.
The ServerHello has no ALPN extension, and the template must use record version 0x0303.
The fake certificate record matches the largest first-flight ApplicationData record of the mask host.
It contains random bytes of the correct size, not the certificate DER in plaintext.

The TLS profile fetch retries with backoff.
`general.trusted-proxy-cidrs` limits which TCP peers can send a PROXY protocol header on the main listener.
The default is empty, which allows any peer, as before.

`telego doctor` warns when the mask host does not negotiate `X25519MLKEM768`.
It also warns when the A and AAAA records of the mask host do not include the proxy public IP.
These warnings do not make the command fail.

## Relay and WEB carrier

Stall detection now uses the acknowledged-byte count from `TCP_INFO` and partial drain of the output buffer.
A slow client that keeps reading is not closed.
A direct relay closes after 100 seconds without progress in one direction.
The WEB write timeout now applies only when a write makes no progress.

The WEB carrier drains early responses before it closes a connection.
Owned writes wake the drain path directly instead of polling every 5 ms.
Downloads set `X-Accel-Buffering: no`.

Hot paths use fewer copies and allocations.
This includes EE batch buffers, ClientHello authentication, per-user connection limits, and Middle-End request framing.

## Middle-End

When the active link fails, Telego publishes a ready candidate link at once.
Repeated rotation failures back off.
The NAT probe no longer depends on the context of the caller.

Close requests have a share of the queue for each slot, and duplicate stale closes are dropped.
A remote close cancels pending requests, and reservations that Telego already handed out stay valid.
A busy loop in the dispatcher after a lease is invalidated is fixed.
SOCKS5 connect and handshake steps have time limits.
Telego makes no new dials after the Middle-End runtime stops.

## Metrics

New counters:

- `telego_connection_closes_total{reason}` counts why each relayed client connection closed.
- `telego_mask_fallbacks_total{reason}` counts connections sent to the mask host.
- `telego_replay_cache_evictions_total` counts replay entries evicted before their TTL.
- `telego_web_websocket_closes_total{reason}` counts closes of WEB WebSocket carriers.
- `telego_web_http_write_timeouts_total` counts WEB HTTP carrier write timeouts.

At debug level, Telego logs one line for each counted close, with the reason, route, and age.
The README lists all reasons.

## SYN limit

`synlimit.sh` now uses a generic burst of 24, the same as telemt 3.5.0.
The new `dist/synlimit@.service` unit applies the rules at boot. It is optional.

## Dependencies

Updated `golang.org/x/crypto` to 0.59.0.
The x/crypto packages in the release binary are the same as in 0.58.0.
Updated gotd/td to 0.165.0. Only the `dcfetch` tool uses it.
Updated Playwright to 1.65.1, pyee to 16.0.2, and the CI Node.js pin to the 26.13.1 security release.

Go 1.27.4 is still the latest stable release.
All declared Go and Python dependencies, CI actions, and container image pins are at their latest compatible versions.
Unused upstream module-graph entries keep their existing versions.

## Validation

The default race, `gc_opt` race, production-tag, and 32-bit production-tag suites passed.
New regression tests cover the accept backoff, replay keys, the ServerHello template, relay stall detection with slow readers, and each close reason.

## Upgrade

Restart Telego after the binary or container update.

Configuration validation is stricter. Telego does not start if a value is out of range:

- `general.handshake-timeout` must be 0 or between 1 second and 1 minute.
- `performance.client-silence-close` must be 0 or at least 1 second.
- `performance.max-write-buffer-mb` must be at most 1024.
- `general.max-connections` cannot be negative.
- Each `general.trusted-proxy-cidrs` entry must be a canonical CIDR, for example `127.0.0.1/32`.

The default Docker stop timeout is 10 seconds.
Use `docker stop -t 30` or `stop_grace_period: 30s` to allow the full 25-second shutdown.
